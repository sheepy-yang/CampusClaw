# CampusClaw 小组项目选题说明

## 1. 项目题目

**CampusClaw 扩展：备课、命题、批改、讲评与个性化辅导**

本项目在现有 CampusClaw 的登录、角色权限、班级隔离、讲义入库和可追溯混合检索之上，扩展面向教学过程的智能功能，形成备课、命题、作业批改、课堂讨论、课堂讲评、学习诊断和个性化辅导的闭环。

系统按「先检索、再生成、后校验」执行。各项智能功能先检索本班已有讲义，检索结果足以作为依据时才调用模型。教案、试卷、预习单和讲评须经教师确认后，才能发布或写入知识库。

## 2. 主要功能

系统提供九项智能教学功能，每项对应一条可独立开关的技能，教师可按班级启用或关闭。教师与学生的权限区分如下：

- 学生不能使用备课、命题等教师功能。
- 学生不能查看全班讲评、学情诊断和统计。
- 面向学生开放的内容，均须经教师确认。

| 功能 | 做什么 | 约束 |
|---|---|---|
| 智能命题 | 依据本班讲义，按题型、难度和题量生成试卷，由教师逐题采纳后发布 | 引用必须来自本次检索；未采纳任何题目时不能发布；学生提交前看不到答案 |
| 智能备课 | 生成教学目标、教学过程、例题、分层练习和板书，确认后成为本班讲义 | 没有讲义依据的句子不予保留；未确认的教案不能被检索 |
| 主观题错因批改 | 选择题和填空题对照参考答案；简答题进入队列，给出建议分和错因 | 一次只处理一名学生的一道题；依据无法对应原文时交由教师复核；教师改分后以教师分数为准 |
| 班级讲评 | 归纳一次作业的共性错因，并生成讲解提纲和补救题 | 提交人数少于 5 人时不调用模型；全班统计仅教师可见 |
| 学情诊断 | 汇总一段时间内的作业，说明薄弱点、已掌握的知识点及后续建议 | 作答少于 3 次时只标明样本不足；个人报告经教师确认后才发给学生 |
| 复习路径 | 根据该生近两周的错题，安排 3 至 5 步阅读与自测 | 没有错题时不调用模型；路径仅本人可见，自测不计入正式成绩 |
| 预习单 | 课前生成本次课的知识卡片、思考题和客观自测 | 有效卡片少于 3 张时不保存；自测不计入正式成绩 |
| 追问辅导 | 针对已判错的题目逐轮提问，并判断学生是否抓住要点 | 连续两轮抓住要点，或满 4 轮、学生要求讲解之后，才给出最终答案 |
| AI 课堂讨论 | 教师发起讨论题，学生在本班内发言；模型将观点收成最多 4 类，依据讲义归纳并追问尚未说清之处 | 少于 5 人时不调用模型；发言和归纳只在本班可见，送入模型的内容不含姓名；没有讲义依据时不编造结论；讨论纪要经教师确认后才保存，且不计入成绩 |

## 3. 技术方案

在现有 CampusClaw 仓库上继续开发，沿用 Python HTTP 服务、SQLite 和 Qdrant，嵌入与对话网关的密钥只保存在服务端。Docker Compose 在现有 Web 服务和 Qdrant 之外增加 Redis 与批改 worker。讲义切分、向量嵌入和本班混合检索继续使用现有模块，新增的生成逻辑放在智能体层。

九项功能均按先检索、再生成、后校验执行。模型只返回事先约定的结构。引用必须指向本次检索得到的切片，摘录必须是原文中连续出现的文字。浏览器不能提交系统提示，也不能自行指定出处。对话网关不可用时返回 503，此时不保存草稿，也不写入建议分。选择题和填空题直接对照参考答案，不调用模型。

编排层依据登录角色和技能开关选择智能体。模型可通过 MCP 检索本班讲义、读取题目已绑定的切片，以及读取当前用户自己的错题。课堂讨论中，模型只能读取本班本场发言和已检索到的讲义切片。发布作业、确认入库、教师改分和确认讨论纪要都不对模型开放。主观题提交后进入 Redis，由 worker 逐题批改。

业务数据仍写入现有数据库，并新增试卷、教案、批改、讲评、诊断、复习路径、预习单、追问和课堂讨论等表。作业一经发布，题干和引用即被冻结，之后重建索引不会改变已发布的题目。验收在现有测试之外补充以下失败情形：未登录、学生越权、跨班访问、检索没有依据、样本人数不足，以及追问尚未结束就给出最终答案。
